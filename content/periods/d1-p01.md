# 요약

코드를 적는 공책과 그 코드를 실행할 도구를 준비합니다. Jupyter Notebook은 설명과 코드를 함께 저장하는 공책이고, Kernel은 코드를 실제 실행하며 변수를 기억하는 엔진입니다. Anaconda와 uv는 Python과 필요한 도구를 준비하는 방법입니다. 오늘은 빈 실습 폴더에서 `1 + 2`를 실행해 3이 나오는지 확인하며, 데이터 ZIP은 아직 받지 않습니다.

아나콘다의 역할·기본 사용법과 Notebook 첫 실행을 다루고, uv로 수업 환경을 준비한 뒤 Jupyter Notebook에서 셀 실행·저장·Kernel 재시작까지 직접 수행합니다. 첫 시간의 결과물은 다시 실행할 수 있는 Notebook 한 개입니다.



## 수업 위치와 목표

**2026년 10월 6일 · 1일차 1교시.** 첫 단원 3시간 중 실행 환경을 준비하는 시간입니다.

수업이 끝나면 다음 작업을 혼자 할 수 있어야 합니다.

- 아나콘다의 역할과 conda 환경 생성·활성화를 설명하고, Windows Anaconda Prompt 또는 Mac Terminal에서 Notebook을 실행하는 방법을 확인합니다.
- Anaconda 전용 Kernel에서 첫 셀 실행·저장·재실행을 확인하는 절차를 익힙니다.
- `uv run --locked jupyter notebook`으로 기본 실습 환경의 Notebook을 실행합니다.
- 코드 셀과 Markdown 셀의 차이를 설명합니다.
- Shift+Enter로 셀을 실행하고 파일을 저장합니다.
- Kernel 재시작 후 위에서부터 실행하여 결과를 재현합니다.

## 1. 아나콘다 설치 및 Jupyter Notebook 실행 환경 구성

### 아나콘다와 uv로 Notebook 환경 준비하기

아나콘다는 Python과 분석 도구를 묶어 제공하는 배포판이고 conda는 환경·패키지를 관리합니다. 먼저 Anaconda 설치 방법·conda 기본 사용·Notebook 첫 실행을 확인합니다. 그 뒤 두 경로를 비교하고 기본 실습은 **uv → Python → 프로젝트 환경 → Jupyter Notebook**으로 진행합니다.

이 수업에서 필요한 것은 Python, 분석 패키지, Notebook 실행 환경입니다. uv는 Python을 준비하고 폴더별 `.venv`와 의존성을 관리할 수 있어 이 구성에 아나콘다를 추가로 설치할 필요가 없습니다. uv 자체가 Python이나 Notebook을 대신하는 언어는 아닙니다. [uv의 Python 관리](https://docs.astral.sh/uv/guides/install-python/)

| 도구 | 이번 수업에서 맡는 일 |
| --- | --- |
| uv | Python 준비, 프로젝트 환경·패키지 관리, 환경에 맞는 명령 실행 |
| Python | 계산·조건문·반복문 실행 |
| `.venv` | 이 수업의 패키지를 다른 프로젝트와 분리 |
| Jupyter Notebook | 설명·코드·출력을 셀로 묶어 작성 |
| Kernel | 선택한 Python으로 코드 셀 실행, 변수 상태 유지 |

### 명령 창과 Notebook은 이렇게 연결됩니다

### Anaconda 경로 — 기본 사용과 Notebook 첫 실행

**아나콘다의 역할, 환경 생성·활성화, Jupyter Notebook 첫 실행**을 확인합니다. 기존 설치가 있으면 아래 단계를 따라 실행하고, 설치가 없으면 강사 시연에서 환경과 Kernel을 확인합니다. 이어서 기본 실습은 uv로 진행합니다.

**1. 설치 상태 확인.** 이미 Anaconda가 설치되어 있으면 재설치하지 않습니다. Windows는 검색에서 **Anaconda Prompt**, Mac은 **Terminal(터미널)**을 열어 `conda --version`을 실행합니다.

- **Windows 설치:** [Anaconda 공식 Windows 설치 안내](https://www.anaconda.com/docs/getting-started/anaconda/install/windows-gui-install)에 따라 Distribution 설치 파일을 받고 설치 옵션·약관을 확인합니다. 완료 후 Anaconda Prompt를 엽니다.
- **Apple Silicon Mac 설치:** Apple 메뉴의 ‘이 Mac에 관하여’에서 칩을 확인하고, [공식 Mac 설치 안내](https://www.anaconda.com/docs/getting-started/anaconda/install/mac-gui-install)의 **64-Bit (Apple silicon) Graphical Installer** `.pkg`를 선택합니다. 현재 지원 대상은 macOS 12.1 이상입니다. 다운로드한 `.pkg`를 열어 설치 위치·약관을 확인하고 설치 후 Terminal에서 `conda list`를 실행합니다. GUI 기본 위치는 `/opt/anaconda3`입니다. [시스템 요구사항](https://www.anaconda.com/docs/getting-started/anaconda/system-requirements)
- **Intel Mac:** Anaconda는 2025년 8월 15일부터 Intel Mac 신규 패키지·설치 파일을 만들지 않습니다. 기존 Intel 환경은 사용할 수 있고, 기존 `MacOSX-x86_64` 설치 파일은 [공식 archive](https://repo.anaconda.com/archive/)에 남아 있습니다. 최신 Apple Silicon 설치 파일을 Intel Mac에 설치하지 않습니다. 기존 환경이 없으면 시연에서 conda 흐름을 확인한 뒤 아래 uv 실습으로 진행합니다. [Intel 지원 안내](https://www.anaconda.com/blog/intel-mac-package-support-deprecation)

Mac에서 기존 설치가 있는데 `conda: command not found`가 나오면 설치 위치를 확인합니다. GUI 기본 설치라면 다음 명령을 실행하고 Terminal을 다시 엽니다.

```bash
/opt/anaconda3/bin/conda init zsh
```

[Terminal 설치](https://www.anaconda.com/docs/getting-started/anaconda/install/mac-cli-install)의 기본 위치를 사용했다면 `~/anaconda3/bin/conda init zsh`입니다. bash 사용자는 마지막 `zsh`를 `bash`로 바꿉니다. 실제 설치 위치가 다르면 그 위치의 `bin/conda`를 사용합니다. [conda 셸 초기화](https://docs.conda.io/projects/conda/en/stable/commands/init.html)

**2. 수업용 conda 환경 준비.** 다음은 **Windows Anaconda Prompt 또는 Mac Terminal에 입력하는 공통 명령**이며 Notebook 코드 셀에 넣지 않습니다. `base`는 기본 환경이고 `kpc-finance-conda`는 이 첫 교시에서 사용할 별도 환경입니다. 환경을 분리하면 기본 환경의 패키지를 직접 바꾸지 않아도 됩니다.

```text
conda env list
```

목록에 `kpc-finance-conda`가 없다면 한 번만 만듭니다. Python 3.12, 표 분석용 pandas, Notebook, Python Kernel용 ipykernel, Excel용 openpyxl을 함께 준비합니다.

```text
conda create --name kpc-finance-conda python=3.12 pandas notebook ipykernel openpyxl
```

설치 확인 질문에는 패키지 목록을 확인한 뒤 진행합니다. 같은 이름의 환경이 이미 있으면 위 생성 명령은 생략합니다. 환경을 활성화하고 필요한 패키지가 준비되도록 설치 명령을 확인합니다.

```text
conda activate kpc-finance-conda
conda install pandas notebook ipykernel openpyxl
```

Prompt 앞의 `(kpc-finance-conda)`를 확인합니다. `conda env list`의 별표는 현재 활성 환경을 나타냅니다. 환경 생성·활성화는 [conda 공식 환경 관리 문서](https://docs.conda.io/projects/conda/en/stable/user-guide/tasks/manage-environments.html)를 따릅니다.

**3. 전용 Kernel 등록 후 수업 폴더에서 실행.** 활성화한 환경의 Python으로 이름이 구분되는 Kernel을 등록합니다. 같은 이름의 Kernel을 다시 등록하면 해당 등록이 갱신되므로 본 절차의 환경 이름과 Kernel 이름을 일치시킵니다. [IPython 공식 Kernel 등록 안내](https://ipython.readthedocs.io/en/stable/install/kernel_install.html)를 참고합니다.

```text
python -m ipykernel install --user --name kpc-finance-conda --display-name "Python (kpc-finance-conda)"
```

지금은 데이터나 자료 묶음을 다운로드하지 않습니다. 자신의 빈 수업 폴더를 만들고 그 안에서 실행합니다. 이미 폴더가 있으면 `mkdir`는 생략합니다. Windows Anaconda Prompt의 `cd /d`는 폴더와 드라이브를 함께 바꿉니다.

```text
mkdir C:\kpc-finance
cd /d "C:\kpc-finance"
jupyter notebook
```

Mac Terminal:

```bash
mkdir -p ~/kpc-finance
cd ~/kpc-finance
jupyter notebook
```

브라우저가 자동으로 열리지 않으면 Prompt에 표시된 로컬 접속 주소를 브라우저에서 엽니다. Notebook 파일 목록의 기준 위치가 수업 폴더인지 확인합니다. 서버를 시작하는 Prompt 창은 실행 중인 동안 열어 둡니다.

**4. 새 Notebook과 Kernel 선택.** 파일 목록에서 **New Notebook** 또는 새 Notebook 생성 메뉴를 선택하고 **Python (kpc-finance-conda)** Kernel을 고릅니다. 이미 열린 Notebook이면 Kernel 선택/변경 메뉴에서 같은 이름을 선택합니다. 파일 이름은 `01-python-anaconda.ipynb`로 정합니다. uv 실습 파일 `01-python-basics.ipynb`와 구분합니다. 메뉴 위치는 버전에 따라 다를 수 있습니다. [Jupyter 공식 사용 안내](https://jupyter-notebook.readthedocs.io/en/stable/notebook.html)를 참고합니다.

**5. 첫 셀과 실행 환경 확인.** 코드 셀에 입력하고 **Shift+Enter**로 실행합니다.

```python
print("수업 준비 완료")
print(1 + 2)
```

`수업 준비 완료`와 `3`이 출력되는지 확인합니다. 다음 코드 셀에서 실제 Kernel과 자료 위치를 확인합니다.

```python
import sys
from pathlib import Path
import pandas as pd

print("Python:", sys.version.split()[0])
print("실행 파일:", sys.executable)
print("환경:", sys.prefix)
print("pandas:", pd.__version__)
print("자료 폴더:", Path.cwd())
```

Anaconda 경로에서는 실행 파일과 환경이 보통 설치 폴더 아래 Windows `envs\kpc-finance-conda\python.exe`, Mac `envs/kpc-finance-conda/bin/python`을 가리킵니다. 설치 위치는 기기마다 다르며, uv의 수업 `.venv`가 나오면 Kernel을 잘못 선택한 것입니다. `Path.cwd()`는 방금 만든 수업 폴더인지 확인합니다. pandas를 찾지 못하면 Anaconda Prompt/Terminal의 활성 환경과 Notebook의 선택 Kernel부터 확인합니다.

**6. 저장·재실행·종료.** 제목 또는 파일 이름 변경 메뉴에서 위 파일 이름을 확인하고 Windows는 **Ctrl+S**, Mac은 **Cmd+S** 또는 저장 버튼으로 저장합니다. **Shift+Enter는 두 OS에서 동일합니다.** Kernel 재시작 후 위의 두 코드 셀을 처음부터 실행해 같은 출력이 나오는지 확인하고 다시 저장합니다. 실행을 마칠 때 Anaconda Prompt/Terminal에서 **Ctrl+C**를 누르고 종료 확인에 응답한 뒤 `conda deactivate`로 환경을 빠져나옵니다. **Mac도 Control+C로 서버를 종료합니다.** 브라우저 탭을 닫는 것만으로 서버가 종료되지는 않습니다. [Jupyter 조작](https://jupyterlab.readthedocs.io/en/stable/user/commands.html), [서버 실행과 종료](https://docs.jupyter.org/en/latest/running.html)

### 두 경로 비교 후 uv 기본 실습으로 전환

| 구분 | Anaconda로 첫 실행 확인 | 본 수업의 uv 기본 실습 |
| --- | --- | --- |
| 명령 입력 위치 | Windows Anaconda Prompt / Mac Terminal | 새 Windows PowerShell / Mac Terminal의 수업 폴더 |
| 환경 | `conda activate kpc-finance-conda` | `uv init`과 `uv add`로 실습 `.venv` 준비 |
| 서버 실행 | 활성 환경에서 `jupyter notebook` | `uv run --locked jupyter notebook` |
| Kernel 확인 | Windows `envs\kpc-finance-conda\python.exe` / Mac `envs/kpc-finance-conda/bin/python` | Windows `.venv\Scripts\python.exe` / Mac `.venv/bin/python` |
| 파일 | `01-python-anaconda.ipynb` | `01-python-basics.ipynb` |

두 경로 모두 Python과 필요한 패키지를 준비하여 Notebook 코드 셀을 실행합니다. 이후 기본 실습에서는 데이터가 없는 수업 폴더에서 프로젝트와 패키지를 준비하는 uv 방식을 사용합니다. Anaconda 서버를 종료하고 `conda deactivate`한 뒤 새 PowerShell/Terminal에서 아래 uv 절차를 진행합니다. Mac 새 Terminal이 `(base)`로 시작하면 다시 `conda deactivate`합니다. Notebook을 바꿔 열었을 때도 `sys.executable`로 Kernel을 확인합니다. conda 환경에서 `uv sync`를 실행하거나 uv 실습의 패키지를 conda 환경에 설치하는 식으로 두 경로를 섞지 않습니다.

### Windows에서 uv 준비

**PowerShell**을 열고 다음 명령을 실행합니다. 이미 uv가 있으면 설치는 생략하고 버전 확인부터 합니다.

```powershell
winget install --id=astral-sh.uv -e
```

설치 후 PowerShell을 새로 열고 `uv --version`을 실행합니다. WinGet을 쓸 수 없으면 [uv 공식 설치 문서](https://docs.astral.sh/uv/getting-started/installation/)의 Windows 방법을 따릅니다.

### macOS에서 uv 준비

Terminal에서 아래 명령을 입력합니다. 기본 셸 zsh와 bash에서 모두 사용할 수 있습니다. 이미 uv가 있으면 설치는 생략합니다.

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

설치 후 Terminal을 다시 열고 `uv --version`을 확인합니다. [uv 공식 설치](https://docs.astral.sh/uv/getting-started/installation/), [Mac Terminal 셸](https://support.apple.com/guide/terminal/change-the-default-shell-trml113/mac)

### 빈 폴더에서 실습 환경 만들기

지금은 데이터 파일이나 실습 자료를 다운로드하지 않습니다. 영문 이름의 수업 폴더에서 환경을 준비합니다. 앞의 Anaconda 확인에서 폴더를 이미 만들었다면 `mkdir`는 생략합니다. PowerShell에서는 아래 명령을 한 줄씩 실행합니다. CMD에서 다른 드라이브의 폴더로 이동할 때는 `cd /d 폴더경로`를 사용합니다.

```powershell
mkdir C:\kpc-finance
cd C:\kpc-finance
uv init --bare --python 3.12
uv python pin 3.12
uv python install 3.12
uv add pandas notebook ipykernel openpyxl numpy matplotlib seaborn scikit-learn beautifulsoup4 selenium yfinance
uv run python -m ipykernel install --user --name kpc-finance-uv --display-name "Python (kpc-finance-uv)"
uv run jupyter notebook
```

Mac Terminal에서는 다음 순서로 실행합니다. 앞의 Anaconda 확인에서 폴더를 이미 만들었다면 `mkdir`는 생략합니다. `~`는 자신의 홈 폴더이고 Windows의 `C:\`와 `cd /d`는 Mac에 사용하지 않습니다.

```bash
mkdir -p ~/kpc-finance
cd ~/kpc-finance
uv init --bare --python 3.12
uv python pin 3.12
uv python install 3.12
uv add pandas notebook ipykernel openpyxl numpy matplotlib seaborn scikit-learn beautifulsoup4 selenium yfinance
uv run python -m ipykernel install --user --name kpc-finance-uv --display-name "Python (kpc-finance-uv)"
uv run jupyter notebook
```

`uv run`에는 별도 환경 활성화가 필요 없습니다. 직접 활성화가 필요한 경우만 Windows PowerShell의 `.venv\Scripts\Activate.ps1`, Mac Terminal의 `source .venv/bin/activate`를 사용합니다. [uv 환경 안내](https://docs.astral.sh/uv/pip/environments/)

`uv python pin 3.12`는 실행할 Python 계열을 지정합니다. `uv add`는 필요한 패키지와 잠금 파일을 함께 관리합니다. 위 명령은 현재 폴더에 `pyproject.toml`·`uv.lock`·`.python-version`과 `.venv`를 만듭니다. 준비 후 `uv run python --version`으로 수업용 Python 버전을 확인합니다. `.venv` 폴더를 다른 PC로 복사하는 대신 설정과 잠금 파일로 각 PC에서 환경을 만듭니다.

### Notebook 생성과 Kernel 확인

코드 복사·붙여넣기는 Windows **Ctrl+C / Ctrl+V**, Mac **Cmd+C / Cmd+V**입니다. 코드 셀 실행은 둘 다 **Shift+Enter**입니다. 터미널의 서버 중단은 복사와 구분하여 둘 다 **Control+C**를 사용합니다.


위 등록 명령으로 만든 **Python (kpc-finance-uv)** Kernel을 선택합니다. 다른 환경의 Python 3가 보이면 이름만 보고 선택하지 말고 이 Kernel로 바꿉니다. `sys.executable`이 맞지 않으면 프로젝트 폴더에서 등록 명령을 다시 실행한 뒤 Kernel 변경 메뉴에서 다시 선택합니다. [Kernel 등록](https://ipython.readthedocs.io/en/stable/install/kernel_install.html)

브라우저의 Notebook 화면에서 새 Notebook을 만들고 Python Kernel을 선택합니다. 이름을 `01-python-basics.ipynb`로 저장합니다. 첫 코드 셀을 **Shift+Enter**로 실행합니다. [uv와 Jupyter 공식 안내](https://docs.astral.sh/uv/guides/integration/jupyter/)처럼 프로젝트 환경과 Kernel의 연결을 확인합니다.

```python
print("수업 준비 완료")
print(1 + 2)
```

출력은 `수업 준비 완료`와 `3`입니다. 다음 셀에서 Python의 위치와 패키지 버전을 확인합니다.

```python
import sys
from pathlib import Path
import pandas as pd

print("Python:", sys.version.split()[0])
print("실행 파일:", sys.executable)
print("pandas:", pd.__version__)
print("자료 폴더:", Path.cwd())
```

실행 파일이 Windows에서는 수업 폴더의 `.venv\Scripts\python.exe`, Mac에서는 `.venv/bin/python`인지 확인합니다. 이번 시간에는 새로 만든 실습 폴더에 Notebook을 저장합니다. 다른 Kernel이면 서버를 종료하고 수업 폴더에서 `uv run --locked jupyter notebook`으로 다시 엽니다. 패키지를 추가할 때도 서버를 멈추고 PowerShell/Terminal에서 강사가 안내한 `uv add 패키지이름`을 사용한 뒤 다시 확인합니다.

저장은 Windows **Ctrl+S**, Mac **Cmd+S**입니다. 셀 실행 **Shift+Enter**는 두 OS에서 같습니다. 실행 중단은 **Kernel → Interrupt Kernel**, 재시작은 **Kernel → Restart Kernel**, 전체 재실행은 **Restart Kernel and Run All Cells** 메뉴를 사용합니다. 메뉴 이름은 버전·표시 언어에 따라 조금 다를 수 있습니다. 서버 종료는 PowerShell/Terminal에서 두 OS 모두 **Ctrl+C**입니다. [Jupyter 조작 안내](https://jupyterlab.readthedocs.io/en/stable/user/commands.html)

Notebook의 변수는 **실행한 셀의 순서**에 따라 저장됩니다. 아래에서는 셀 A를 먼저 실행하고 셀 B를 실행합니다.

셀 A:

```python
base_price = 10000
```

셀 B:

```python
print(base_price + 500)
```

예상 출력은 `10500`입니다. Kernel을 재시작하면 변수 값이 지워지므로 A부터 다시 실행해야 합니다. 이 동작은 [Jupyter 코드 실행 설명](https://jupyter-notebook.readthedocs.io/en/stable/examples/Notebook/Running%20Code.html)에서 확인할 수 있습니다.

**직접 실습:** 출력 문구를 자신의 문구로 바꾸고 실행하세요. 파일을 저장한 뒤 Kernel을 재시작하고 셀을 위에서부터 실행하여 같은 결과가 나오는지 확인하세요.

## 화면에서 구분할 세 가지

**Windows PowerShell 또는 Mac Terminal**에는 `uv add pandas notebook ipykernel`과 `uv run jupyter notebook` 같은 실행 명령을 넣습니다. **코드 셀**에는 `print(...)`처럼 Python 코드를 넣습니다. **Markdown 셀**에는 제목과 수업 메모를 씁니다. 같은 글자를 넣어도 어디에 넣었는지에 따라 처리 방식이 달라집니다.

Notebook의 셀을 클릭하면 입력 내용을 수정할 수 있습니다. Shift+Enter는 현재 셀을 실행하고 다음 셀로 이동합니다. 코드 셀 마지막 줄에 값이나 변수 이름만 적으면 Notebook이 그 값을 보여줍니다. `print()`는 여러 줄을 명시적으로 출력할 때 사용합니다.

Markdown 셀로 바꾼 뒤 아래 문장을 입력하고 실행합니다. 메뉴 이름은 Notebook 버전에 따라 조금 다를 수 있으므로 셀 유형 선택 메뉴에서 Markdown을 고릅니다.

```markdown
# 나의 첫 분석 노트

오늘은 Python 코드를 실행하고 결과를 저장합니다.
```

제목은 큰 글씨로, 설명은 일반 문장으로 표시됩니다. 셀 유형을 다시 Code로 바꿀 때에는 기존 설명이 Python 코드로 실행되지 않도록 새 셀을 사용합니다.

## 저장된 파일과 Kernel의 기억

저장하는 `.ipynb` 파일에는 코드·설명·출력 등이 들어갑니다. 현재 실행 중인 변수는 Kernel의 메모리에 있습니다. 파일을 저장했다고 변수를 만드는 셀을 실행할 필요가 없어지는 것은 아닙니다.

1. `base_price = 10000` 셀을 실행합니다.
2. `print(base_price + 500)` 셀을 실행하여 `10500`을 확인합니다.
3. Kernel 재시작을 선택합니다.
4. 두 번째 셀만 실행하여 `NameError`를 관찰합니다.
5. 첫 셀부터 다시 실행하여 결과가 복구되는지 확인합니다.

이 실험은 오류를 일부러 경험하는 활동입니다. 오류를 확인한 뒤 마지막에는 위에서부터 전체 실행하여 오류 출력이 남지 않게 저장합니다.

## 흔한 오류와 복구

| 현상 | 원인 확인과 복구 |
| --- | --- |
| `uv`가 인식되지 않음 | uv 설치 후 Windows PowerShell/Mac Terminal을 새로 열고 `uv --version`을 확인합니다. |
| Notebook 셀에서 `uv sync`가 오류 | 셸 명령을 코드 셀에 입력했습니다. 수업 폴더의 PowerShell/Terminal에서 실행합니다. |
| `ModuleNotFoundError: pandas` | `uv add pandas` 후 `uv run jupyter notebook`으로 실행했고 `sys.executable`이 수업 `.venv`인지 확인합니다. |
| 셀에 문장만 보이고 결과가 없음 | Code/Markdown 유형과 Shift+Enter 실행 여부를 확인합니다. |
| `NameError` | 변수 정의 셀부터 다시 실행합니다. 재시작하면 이전 변수는 사라집니다. |
| 실행 중 표시가 계속됨 | 실행 중인 작업을 확인하고 Kernel의 실행 중단 메뉴를 사용합니다. 필요한 경우 재시작 후 위에서부터 실행합니다. |
| 파일을 어디에 저장했는지 모름 | `Path.cwd()`와 Notebook 파일 목록에서 파일 이름을 확인합니다. |
